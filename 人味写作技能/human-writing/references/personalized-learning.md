# 个性化学习系统

本文档说明人类化写作助手的个性化学习机制。

## 系统概述

个性化学习系统让Skill"越用越好"，通过持续学习用户的表达习惯、风格偏好、认知水平，实现真正的个性化写作辅助。

## 核心原理

### 问题背景

传统AI写作助手的问题：
- 使用通用规则，不考虑用户个人风格
- 无法记住用户的偏好
- 每次使用都从零开始
- "直男味"：只给"对"的东西，不考虑用户感受

### 解决方案

通过配置文件存储用户偏好，让智能体：
1. 记住用户的表达习惯
2. 理解用户的风格偏好
3. 适应用户的认知水平
4. 根据用户反馈持续学习

## 配置文件

### 文件位置

推荐位置（按优先级）：
1. 项目根目录：`./.human-writing-config.json`
2. 用户目录：`~/.human-writing-config.json`

### 配置文件结构

详见：[assets/user-profile-template.json](../assets/user-profile-template.json)

### 主要字段说明

#### 表达风格 (expression_style)
- **formal_level** (0-1): 正式程度
- **slang_usage** (0-1): 俚语使用频率
- **favorite_words**: 常用词汇列表
- **aversion_words**: 避免使用的词汇

#### 认知水平 (cognitive_level)
- **abstract_preference** (0-1): 抽象偏好程度
- **example_preference** (0-1): 例子偏好程度
- **detail_level** (0-1): 细节程度

#### 写作偏好 (writing_preferences)
- **avoid_definitions**: 是否避免抽象定义
- **keep_imperfections**: 是否保留不完美表达
- **personal_experience**: 是否使用个人经验
- **show_consequences**: 是否展示表达后果/风险

#### 肉身感水平 (embodiment_level)
- **use_body_sensations**: 是否使用身体感受
- **use_context_specific**: 是否使用具体情境
- **show_vulnerability**: 是否展示脆弱性

## 工作流程

### 1. 初始化阶段（首次使用）

**检测配置文件**：
```
检查 ~/.human-writing-config.json 或 ./.human-writing-config.json 是否存在
```

**如果不存在**：
- 引导用户初始化配置
- 通过问答收集基本信息
- 创建默认配置文件

**问题示例**：
- 你平时写作喜欢正式一点还是随意一点？
- 你常用哪些口头禅或习惯用语？
- 你喜欢用具体例子还是抽象理论？
- 你希望写作中包含个人经验吗？

### 2. 使用阶段（每次写作）

**读取配置**：
- 读取用户配置文件
- 解析用户偏好参数
- 根据偏好调整写作策略

**个性化应用**：
```
用户偏好：slang_usage = 0.7（高俚语使用）
应用策略：在适当位置插入口语词、网络用语

用户偏好：avoid_definitions = true
应用策略：减少抽象定义，增加具体描述

用户偏好：show_vulnerability = true
应用策略：添加个人失败经历、承认不完美
```

### 3. 学习阶段（持续改进）

**观察用户反馈**：
- 用户是否接受了修改？
- 用户是否拒绝了某些表达？
- 用户是否有新的偏好？

**记录学习历史**：
```json
{
  "date": "2024-02-25",
  "feedback": "用户喜欢口语化的表达",
  "accepted_changes": ["使用'贼'代替'非常'"],
  "rejected_changes": ["使用网络用语'yyds'"],
  "style_adjustment": {
    "formal_level": -0.1,
    "slang_usage": +0.1
  }
}
```

**更新配置文件**：
- 根据学习历史调整偏好参数
- 添加新的常用词到favorite_words
- 移除用户不喜欢的词到aversion_words

## 持续学习机制

### 学习类型

1. **被动学习**：观察用户反馈
   - 用户接受修改 → 增加相关偏好权重
   - 用户拒绝修改 → 减少相关偏好权重

2. **主动学习**：直接询问用户
   - "你更喜欢这种表达吗？"
   - "下次可以用这种方式吗？"

3. **模式识别**：分析用户偏好
   - 发现用户总是拒绝正式表达 → 降低formal_level
   - 发现用户总是喜欢具体例子 → 提高example_preference

### 学习速度

- **快速学习**：明确反馈（"我喜欢这个"）
- **渐进学习**：模糊反馈（"还行吧"）
- **保守学习**：不确定反馈（"再说吧"）

### 避免过度拟合

- 设置学习上限（偏好参数范围0-1）
- 定期校准（每10次使用后询问用户确认）
- 保持一定的通用性（不要完全个性化）

## 使用示例

### 示例1：初始化配置

**智能体**：
"第一次使用，我需要了解你的写作偏好：
1. 你平时写作偏向正式还是随意？（1-10分）
2. 你常用哪些口头禅或习惯用语？
3. 你喜欢用具体例子还是抽象理论？
4. 你希望写作中包含个人经验吗？
5. 你写作的受众是谁？"

**用户**：
"7分偏向随意，常用'贼'、'挺'、'那啥'，喜欢具体例子，包含个人经验，受众是普通读者。"

**智能体**：
"好的，已创建你的配置文件。下次写作会根据这些偏好调整。"

### 示例2：个性化应用

**原文**：
"在现代软件开发中，敏捷开发方法非常重要，能够显著提升团队协作效率。"

**通用优化**：
"敏捷开发在软件开发中很关键，能帮助团队更好地合作。"

**个性化优化（考虑用户偏好：slang_usage=0.8, formal_level=0.3）**：
"敏捷开发，贼重要。真的，团队协作效率直接起飞。"

### 示例3：持续学习

**场景**：用户多次拒绝使用网络用语"yyds"

**学习记录**：
```json
{
  "date": "2024-02-25",
  "rejected_changes": ["使用'yyds'"],
  "style_adjustment": {
    "slang_usage": -0.1
  }
}
```

**配置更新**：
```json
{
  "slang_usage": 0.7,  // 从0.8降到0.7
  "aversion_words": ["yyds"]  // 添加到避免词列表
}
```

## 最佳实践

### 1. 定期校准

每10-20次使用后，询问用户：
"你觉得我最近的理解准确吗？需要调整什么吗？"

### 2. 保守学习

初期学习幅度要小，避免过度个性化导致错误理解。

### 3. 版本管理

使用Git管理配置文件，便于追溯和回滚：
```bash
git add .human-writing-config.json
git commit -m "更新用户偏好：增加口语化程度"
```

### 4. 备份配置

定期备份配置文件到云端，避免丢失学习成果。

### 5. 多场景管理

不同写作场景可以使用不同配置：
- `.human-writing-work.json`（工作场景）
- `.human-writing-personal.json`（个人场景）
- `.human-writing-blog.json`（博客场景）


## 常见问题

### Q: 配置文件会被误删吗？

A: 建议使用Git管理配置文件，定期备份到云端。

### Q: 学习会不会越来越偏？

A: 设置学习上限和定期校准机制，避免过度拟合。

### Q: 多人共用一个设备怎么办？

A: 每个人使用不同的配置文件名，如 `.human-writing-user1.json`。

### Q: 隐私问题？

A: 配置文件仅存储在本地，不会上传到云端。

## 技术实现

2. 解析JSON，提取偏好参数
3. 根据参数调整写作策略
4. 使用 `write_file` 工具更新配置文件

标准JSON格式，易于读写和版本管理。

### 依赖

无需额外依赖，使用标准JSON格式。
