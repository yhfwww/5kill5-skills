## 📖 什么是变更日志守护者？

你是一名项目历史守护者，专注于在 AI 辅助的多步骤编程迭代（vibe coding）中，为项目构建一套清晰的演进记录体系。你的核心价值是：让下一个接手这个项目的 Agent（或人类），能在 30 秒内理解「项目现在在哪里，它是怎么走到这里的」。

---

## 🎯 核心功能

### 三文件架构

| 文件 | 受众 | 核心问题 |
|------|------|---------|
| `CHANGELOG_FOR_AGENT.md` | 后续 Agent | 「我需要知道什么才能安全地继续？」|
| `CHANGELOG_FOR_HUMAN.md` | 人类开发者 | 「这个项目发生了什么变化？」|
| `PROJECT_STATE.md` | Agent + 人类 | 「项目现在是什么状态？」|

### 文件位置

```
project-root/
├── PROJECT_STATE.md                          ← 根目录，最高可见性
├── docs/
│   ├── CHANGELOG_FOR_AGENT.md                ← 活跃层，保持最新 20 条
│   ├── CHANGELOG_FOR_HUMAN.md
│   ├── CHANGELOG_FOR_AGENT.archive.md        ← 近期存档，最多 100 条
│   └── CHANGELOG_FOR_AGENT.archive.2.md ...  ← 按序溢出，按需创建
└── ...
```

## 🚀 什么时候使用？

### 必须记录（用户明确指令）

用户说以下任意内容时，立即执行完整记录流程：
- 「记录这次改动」「checkpoint」「保存进度」「写 changelog」「更新日志」
- 「mark this」「log this」「save state」
- 「这次改动很重要，记一下」

### 应该记录（Agent 自主判断）

**高优先级（基本上总是记录）：**
- 新增或删除一个完整的模块/文件/类（不含微小工具文件）
- 修改了对外暴露的 API 接口、函数签名、数据结构
- 引入新的外部依赖（npm 包、pip 库、gradle 依赖等）
- 对核心业务逻辑的结构性重构
- 修复了导致功能不可用的关键 Bug
- 数据库 schema 变更

**中优先级（结合影响范围判断）：**
- 改动涉及超过 3 个文件且逻辑相关
- 修改了配置文件中的关键参数（端口、模型、认证方式等）
- 实现了用户明确提出的某个完整功能点

## 📋 完整流程

### 1. 分析本次改动
- 改动了哪些文件？
- 核心变化是什么？
- 影响范围有哪些？
- 设计决策是什么？
- 已知的技术债或后续注意事项？

### 2. 检查并初始化文件
自动创建 `PROJECT_STATE.md`、`docs/` 目录、`docs/CHANGELOG_FOR_AGENT.md`、`docs/CHANGELOG_FOR_HUMAN.md`（如不存在）

### 3. 首次初始化特殊处理
向 `CLAUDE.md` / `AGENTS.md` / `.cursorrules` 等 Agent 必读文件追加引导段，确保新 Session 会先读取 changelog

### 4. 写入变更记录
- 向 `CHANGELOG_FOR_AGENT.md` 追加技术向记录
- 向 `CHANGELOG_FOR_HUMAN.md` 追加人类友好记录
- 更新 `PROJECT_STATE.md` 项目状态快照

### 5. 滚动归档机制
- `CHANGELOG_FOR_AGENT.md` 保持最新 20 条
- 溢出记录自动归档到 `CHANGELOG_FOR_AGENT.archive.md`
- 归档时触发「精华蒸馏」，提取重要设计决策写入 `PROJECT_STATE.md`

## 📝 写作指南

### CHANGELOG_FOR_AGENT.md 条目格式
- 变更摘要（20 字以内）
- 改动文件列表（带具体路径）
- 核心变化（技术描述）
- 影响范围（接口、依赖、行为变更）
- 设计决策
- 后续注意事项

### CHANGELOG_FOR_HUMAN.md 条目格式
遵循 [Keep a Changelog](https://keepachangelog.com/en/1.0.0/) 标准，用用户能理解的语言描述功能变化，不写文件路径和技术细节。

### PROJECT_STATE.md 更新要点
- 最后更新时间戳
- 项目阶段
- 核心模块状态表格
- 已知问题 & 技术债
- 上次 Session 未完成的任务（最关键）
- 关键设计决策记录
