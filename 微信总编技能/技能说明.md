# 微信总编技能说明

## 1. 技能概述

`wechat-editor-in-chief`（微信总编）负责将主题、素材、观点或初稿发展为适合微信公众号发布的文章，统筹资料搜集、选题角度、写作、改稿、配图和排版，并检查最终交付质量。

技能不绑定具体账号、行业、署名或文体。它根据文章目的选择研究和表达方式，默认先搜集资料、综合分析，再组织创作；用户明确仅需润色或仅使用指定素材时，遵守该范围。

## 2. 适用场景

- 从一个主题开始，完成资料研究、写作、配图与发布稿整理。
- 将零散素材或观点组织为有主线的公众号文章。
- 修改已有初稿，改善叙述、结构与可读性，并复核事实。
- 制作知识科普、观点评论、人物故事、生活文化、商业行业、实用指南或品牌文章。
- 输出 Markdown、可复制带格式正文的 HTML，以及配套图片和素材包。

本技能用于文章创作与发布前整理，不负责自动运营账号。制作文章不代表授权登录、上传素材或实际发布。

## 4. 协作技能与运行依赖

微信总编负责统筹，具体写作与配图引用以下技能：

| 依赖 | 职责 | 本项目情况 |
| --- | --- | --- |
| `human-writing` | 自然叙述、润色和去除空话 | 已有 `人味写作技能/human-writing/`，运行时仍以环境实际加载的版本为准 |
| `words-to-visuals` | 视觉方向、图像计划、素材生产和验收 | 本次未随微信总编目录复制，需要在使用环境中另行提供 |

生成插画按 `words-to-visuals` 的 imagegen 路由执行；精确图表使用确定性绘图工具。缺失协作技能时，应说明具体缺失项并继续可独立完成的工作，不能声称已经调用。

本地渲染脚本使用 Python 3 标准库，无需安装第三方 Python 包，也不发起网络请求。文章研究和图片制作所需工具由实际运行环境提供。

## 5. 标准工作流程

1. **建立简报**：读取当前对话、素材、初稿及项目 `REF` 等参考目录，明确读者、目的、口吻、篇幅与交付范围。沿用已知信息，只询问影响成稿的关键缺口。
2. **研究与选材**：搜集必要的背景、事实、案例和观点，核对证据，处理材料间的冲突与空缺，再确定中心问题、叙事线或核心判断。
3. **写作与改稿**：应用 `human-writing`，按题材组织内容，避免资料拼贴、空话和编造个人经历。修改后重新核对标题、正文、结论与图注。
4. **配图与图表**：应用 `words-to-visuals`，按内容需要选择图片类型与数量，检查成品，并记录来源、权利状态及生成提示词等信息。纯文字任务不强制配图。
5. **排版与验证**：从同一份 JSON 生成 Markdown 和 HTML，检查桌面、手机宽度、图片加载、正文复制范围、标题复制与失败提示。
6. **交付**：完整创作默认提供 Markdown、HTML、实际使用的独立图片和素材 ZIP；根据题材补充摘要、分享或评论区表达、来源与核验记录。

配图遵循协作技能中的方向、样图确认规则及明确的一次交付例外；不额外设置常规大纲审批关卡。用户仅要求草稿或局部修改时，按实际范围交付。

```text

```

## 7. 本地渲染方法

先按 [HTML 发布规范](wechat-editor-in-chief/references/html-publishing.md) 准备可信的本地文章 JSON。以下命令从项目根目录运行：

```powershell
python -X utf8 "微信总编技能/wechat-editor-in-chief/scripts/render_wechat.py" --article "article.json" --out "output/article-v1" --stem article-final
```

`--out` 指定的目录及对应素材 ZIP 必须尚不存在；改稿使用新的版本目录，避免覆盖旧稿。脚本通过自身位置查找模板，不依赖个人电脑上的固定技能路径。

文章 JSON 的 `title` 和 `blocks` 必填，支持段落、二三级标题、引用、提示和图片。文本仅支持简单加粗、行内代码及 HTTP(S) 链接，不是完整 Markdown 解析器；表格和数据图需另行绘制成 PNG。详细字段与示例见上述发布规范。

输出包括：

- `article-final.md` 与 `article-final.html`。
- `images/` 下的独立图片。
- `image-manifest.json` 图片清单。
- `发布说明.txt`。
- 输出目录旁的 `article-v1-素材包.zip`。

HTML 内嵌图片，可离线打开；Markdown 使用图片的导出绝对路径，移动目录后需更新链接。HTML 支持分别复制标题和正文，但微信可能清洗样式或丢失图片，粘贴后仍需检查图片和手机预览。

## 8. 验收与维护

内容验收关注事实、引用、图片和结论是否一致，是否回应文章目的，是否存在编造经历或混淆概念图与真实证据。排版验收关注 MD 与 HTML 是否同稿、复制正文是否排除标题和操作控件、失败提示是否真实，以及图片能否独立取得。

页面内复制载荷验证与微信后台实际粘贴验证应分别记录，不能将前者描述为后者。
