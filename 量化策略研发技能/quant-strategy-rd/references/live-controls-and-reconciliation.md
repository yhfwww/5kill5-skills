# 实盘控制与对账

本参考只适用于真实自动下单、共享账户或高影响资金风险。它不要求特定经纪商、交易所或资产类别；项目必须将规则映射到所用平台实际支持的订单、仓位和账户语义。

## 1. 分离意图和许可

策略层输出带来源与版本的 `target` 或 `order_plan`，而不是直接调用交易 API。独立交易许可层在每次提交前使用账户事实、风险限制和运行状态决定 `allow / reject / reduce / halt`。普通网页参数、策略配置或模型输出不能绕过该层。

许可检查按适用性选择：市场是否可交易、数据和价格是否新鲜、订单数量/名义/价格保护、速率限制、账户可用资金、单品种和组合净敞口、总名义、杠杆/保证金、日损/回撤、集中度、共享账户中其他策略的预留风险，以及平台特有的限制。拒绝必须留下机器可读原因；出现不确定性时默认阻止风险增加。

## 2. 急停与人工操作

将三种动作明确分开：

1. **禁新单**：保留持仓但阻止任何新的风险增加。
2. **撤销挂单**：停止仍在市场中的未成交订单，结果须核实。
3. **减仓/平仓**：产生新的交易，必须按实际仓位、流动性与用户授权执行。

急停应尽量独立于可能已失效的策略循环、Web UI 和行情处理流程；同时记录触发人/规则、时间、影响账户、当时订单和恢复条件。恢复不应自动发生，至少需要新鲜账户对账、未完成订单检查、数据/健康检查和明确授权。

## 3. 对账服务目标

为策略定义实际可执行的对账频率与升级时限，而不是笼统声称“会对账”。至少明确以下比较：

| 比较对象 | 关键字段 | 差异后的默认动作 |
|---|---|---|
| 本地订单意图与外部订单 | 幂等键、订单 ID、状态、累计成交、均价、费用 | 停止重复提交并查询终态 |
| 本地预期仓位与外部实际仓位 | 市场、方向、数量、保证金/抵押、更新时间 | 冻结新增风险，进入人工或已定义的降险流程 |
| 配置/代码版本与运行状态 | 策略版本、配置指纹、schema、迁移状态 | 阻止不兼容恢复或新订单 |
| 数据/风险快照与已提交订单 | 快照时间、价格、限制检查、原因码 | 作为审计证据，异常时触发复核 |

同一账户的多个策略需有一个账户级视图，不能各自用局部状态认定风险安全。对账的容忍度、频率和升级窗口应由最小可交易单位、平台延迟、策略频率和允许风险决定，并在策略卡中写明。

## 4. 可靠性验证

将失败模式纳入离线或受控环境的验证：断网、重复回报、乱序消息、API 限流、部分成交、交易所延迟、进程崩溃、磁盘写满、时钟漂移、配置不匹配、人工改仓和双进程竞争。测试目标是证明系统会停在可解释状态、保存证据并阻止错误加仓，不是证明它能自动掩盖所有故障。

对于平台支持的功能，核对取消后回报、断线撤单、价格保护、减仓专用订单和自成交防护的实际语义。不要根据名称假定这些功能一致；以锁定 SDK/REST 文档、测试环境或最小受控验证为准。
