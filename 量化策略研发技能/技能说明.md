# 量化策略研发技能说明

## 1. 技能概述

`quant-strategy-rd` 是一个面向量化策略研究、交易系统开发与审查的 AI Agent Skill。它帮助用户把策略从数据和假设，逐步落实为信号、目标仓位、风险约束、执行、对账及可复核证据。

该技能强调：回测收益、纸面收益或单个性能指标都不能单独证明策略适合实盘。研究结论应能追溯到数据范围、策略与配置版本、成本假设、验证方法及样本限制；可运行系统则应具有明确的状态、风控、恢复和运维边界。

## 2. 适用场景

适合在以下任务中使用：

- 将交易想法整理成明确、可测试的策略规格。
- 研究或审查信号、数据质量、回测、成本模型、参数实验和样本外验证。
- 开发或审查模拟交易、历史回放、shadow、dry-run 和交易执行系统。
- 检查仓位计算、订单状态、部分成交、超时、重启恢复、对账和风险控制。
- 为可运行策略设计日志、监控、发布、版本化打包和跨平台部署流程。
- 审查策略变更的研究证据、准入状态、回退条件及上线准备。

该技能适用于股票、期货、期权、外汇、加密资产等不同市场，也适用于单标的、组合、多腿、做市、趋势、均值回归、套利及网格等策略。它不假设特定交易所、数据源、编程语言或运行环境；这些细节应以项目和平台的实际事实为准。

## 3. 不适用范围与安全边界

- 不用于提供纯市场观点、保证收益或判断某策略必然盈利。
- 不因用户要求研究、编码、回测或 dry-run，就推定用户授权连接交易所、操作真实账户或提交真实订单。
- 默认不连接交易所、不读取或输出密钥、不启动或停止交易程序、不修改真实配置或订单。
- 实盘操作、资金操作及扩大交易授权必须有用户明确授权；策略逻辑不能绕过独立风控、账户级限制、急停和对账控制。
- 遇到未知订单结果、部分成交、仓位漂移、过期数据或重启中断时，不猜测成功；应阻断新增交易，并通过可审计的对账流程确认状态。
- 研究结论应区分已验证事实、观察、推断和待验证假设；不得把历史回测或短期 dry-run 描述为长期盈利证明。

## 5. 标准工作流程

### 第一步：确认任务阶段和授权范围

识别任务属于研究与审查、离线开发测试、历史回放、使用实时数据但不下单的 dry-run，还是用户明确授权的实盘运维。前一阶段的授权不能自动延伸到后一阶段。

### 第二步：核实当前事实

优先检查项目代码、当前配置、策略规格、运行状态和权威平台规则。旧文档、示例、模板或源码推断不能代替当前账户、仓位、参数和部署版本的事实。

### 第三步：选择适用的参考规范

根据任务阅读 `SKILL.md` 指定的参考文档。例如，研究任务使用研究与验证规范；订单执行和恢复任务使用运行时与对账规范；可部署策略再使用交付、发布和密钥规范。

### 第四步：实现并验证

将策略信号、目标仓位、风险检查和订单执行分层。按改动类型进行针对性验证，例如公式与阈值的边界测试、订单状态与恢复测试、配置约束检查、历史回放或持续 dry-run。

### 第五步：如实说明结果

交付时区分已实现、离线测试、历史/回放结果、dry-run 观察、只读账户核对和真实下单验收。明确说明尚未执行的外部操作、数据缺口、未覆盖风险及需要用户决定的参数。

## 6. 使用示例

**整理和检验策略假设：**

```text
使用 quant-strategy-rd，帮我把这个均值回归想法整理成可回测的策略规格，并列出关键假设和验证计划。先只做离线研究，不连接交易所。
```

**审查回测质量：**

```text
使用 quant-strategy-rd，审查这组回测的时间切分、交易成本、样本外验证和潜在前视偏差。请区分已验证事实与待验证假设。
```

**检查执行系统：**

```text
使用 quant-strategy-rd，检查订单超时、部分成交和进程重启时的状态处理与恢复流程。只审查代码，不要启动交易程序或触碰真实账户。
```

**准备部署交付：**

```text
使用 quant-strategy-rd，为这个可运行策略检查日志、运维入口、版本化发布包和回退流程；部署动作先不要执行。
```

## 7. 预期输出

根据任务范围，输出可以包括：

- 可测试的策略规格、数据要求和明确的假设。
- 研究设计、验证方法、风险点及证据限制。
- 代码审查结果、针对性测试或需要补充的状态处理。
- 与风险规模匹配的运行、监控、对账、发布和回退要求。
- 清晰区分已完成事项与尚未执行的实盘、部署或账户操作。

不应仅凭单一回测指标给出“可以实盘”结论，也不应在未验证平台事实的情况下臆造账户、交易所或运行状态。

## 8. 维护建议

- 技能行为和参考文档索引以 `quant-strategy-rd/SKILL.md` 为准；入口规则变更时同步检查本文档。
- 修改某一主题时，以对应的 `references/*.md` 为细节依据，避免在说明文档中重复维护完整规范。
- 新增或移除参考文档时，更新本目录结构和用途列表。
- 验证说明与技能入口一致，尤其检查授权边界、研究证据要求、订单异常恢复及“研究不等于实盘”的约束。
